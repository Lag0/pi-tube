Its Windows backend could delete a verified transcript by handle on supported volumes. Its Linux and macOS checks verified preservation, **not** physical deletion. [The decision on #33](https://github.com/Lag0/pi-tube/issues/33#issuecomment-7141537476) kept that ticket open. Moving a replacement to quarantine was not part of the accepted contract.

On the same date, the [cleanup spec](https://github.com/Lag0/pi-tube/issues/32) assigned manual audio cleanup to [#34](https://github.com/Lag0/pi-tube/issues/34), automatic eviction to [#35](https://github.com/Lag0/pi-tube/issues/35), and protected replacement to [#36](https://github.com/Lag0/pi-tube/issues/36). None of those paths was delivered by #37. The paid-work consequence of an automatic retry is discussed in [Paid transcription](paid-transcription.md).

On 2026-11-24, [Lag0/pi-tube@0c7c723](https://github.com/Lag0/pi-tube/commit/0c7c723) merged [PR #53](https://github.com/Lag0/pi-tube/pull/53) and closed [#52](https://github.com/Lag0/pi-tube/issues/52). A preview had appended an audit event, which could expire older history. With Bun’s own cache isolated from the observed disposable home, the real CLI left an empty home empty and preserved every seeded path and byte, including the old audit month, in age and space previews. [CI on reviewed head `4796e88`](https://github.com/Lag0/pi-tube/actions/runs/45504966026) passed on all three systems. This changed preview only: [#34 remains open](https://github.com/Lag0/pi-tube/issues/34#issuecomment-7146868842), and apply, eviction and replacement received no new safety guarantee.

## Current checkout: manual audio cleanup is unavailable

`library prune` without `--include-transcripts` no longer scans or removes audio on any platform, including Windows. An `audio.*` name, age, size or identical contents do not establish that pi-tube created the current file. `keepAudio` does not yet record independent evidence of the version it published. Preview and apply therefore report zero selected or removed, **not** zero audio usage. JSON reports `unsupported: true` and `reason: "unverified_audio_ownership"`; a configured space target is returned as `max_audio_bytes` with `cap_verified: false`. Apply is still audited.

This fence does not deliver verified manual reclaim (#34) or change transcript cleanup (#33). It does not protect automatic eviction (#35) or replacement during retention (#36): those existing paths can still remove or overwrite files by name. Do not use a library containing personal files for audio retention. No files are migrated or adopted.
